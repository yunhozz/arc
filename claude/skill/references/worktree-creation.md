# Claude managed worktree creation

Use this procedure only under the [managed-worktree handoff contract](handoff-worktree.md) after explicit new-managed-worktree selection. Orchestrator creates the approved path, then attaches the session with `EnterWorktree`; directory existence alone proves no attachment.

1. **Selection gate.** Obtain explicit selection of the third path, a new managed worktree and task branch. Before requesting choice, present the source absolute path/repository/common directory, source branch or detached HEAD/full SHA, approved branch candidate and collision status, name/path `.claude/worktrees/<name>` and document scope. Use the verified full source HEAD SHA, never remote HEAD/default branch or automatic fetch.
2. **Pre-creation recheck.** Immediately before creation recheck source state, base SHA, candidate/collision, the absent destination path and availability of `EnterWorktree`. Verify `.claude/worktrees/` is ignored with `git check-ignore`; if not ignored, add `.claude/worktrees/` to `.git/info/exclude` under the approved preparation scope and verify exclusion. Failed checks block creation; changed inputs require fresh explicit choice.
3. **Creation.** Use `git worktree add -b <approved-branch> .claude/worktrees/<name> <verified-full-sha>`. Existing-branch reuse is allowed only under the common contract's approved same-base/not-checked-out exception: use `git worktree add .claude/worktrees/<name> <branch>` and verify HEAD. NEVER use `--force`, `-B`, automatic suffixes or retry with another path or name.
4. **Pre-entry verification.** Before entry verify `git worktree list --porcelain` registration, registered absolute path/realpath, source/target common directory identity, target HEAD equal to the approved full SHA and approved branch. Verify source branch/HEAD/index/files preservation and target dirty state. Approved shared metadata additions are allowed; unexpected state stops dependent work.
5. **Session entry.** Call `EnterWorktree({path:"<abs>"})` with the verified target absolute path. Verify session cwd with a simple `pwd` command and `git rev-parse --show-toplevel` separately; both must resolve to the target realpath. In the worktree session, DO NOT use compound commands containing Git (F5). Perform source checks before entry or after exit, never through a compound Git command in the isolated session.
6. **Attachment attestation.** Record an operator-attested runtime note `type:'worktree-attachment'` with `{realpath, gitDir, gitCommonDir}` from the verified target. For Claude this means `EnterWorktree({path})` succeeded and session cwd and Git toplevel were verified to match the target realpath. Git registration alone is insufficient. Use the existing runtime schema and code unchanged.
7. **Role execution.** The native roles (Planner/Reviewer) inherit session cwd. Pass `--cwd <worktree realpath>` to bridge roles and include the worktree absolute path in every brief. All roles use the verified target and preserve source work.
8. **Exit and preservation.** Return only with `ExitWorktree({action:"keep"})`. No automatic cleanup: `ExitWorktree remove`, `git worktree remove/prune` and branch deletion are forbidden. Preserve the worktree and branch; only Orchestrator may delete them after an explicit user instruction authorizes that deletion.
9. **Stop and inspect.** Creation, registration, entry, identity/base/branch mismatch or partial completion (including branch-only creation or registered worktree with failed entry) stops dependent work. Apply [worktree failures and partial completion](handoff-worktree.md#worktree-failures-and-partial-completion): record exact commands/tool inputs/results, actual source/target paths, branch/HEAD/index/files, common directory, registration, attachment evidence, ownership and completed steps. No automatic retry, fallback (M1/M3), alternate path/name/branch or deletion. Return actual state to Orchestrator; resume only after authorized resolution and full affected-gate revalidation without repeating completed work.
