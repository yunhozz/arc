# Coder handoff

Orchestrator verifies the absolute workspace/repository, branch or detached HEAD, HEAD, staged/unstaged/untracked state, ownership, document approvals and committed planning documents before first start and restart. The approved execution target must remain valid. Claude v1 supports current checkout execution and does not support ARC-managed worktrees.

Resolve the Git common directory (`git rev-parse --path-format=absolute --git-common-dir`) and keep one canonical record at `<git-common-dir>/arc/handoff/<plan-or-task-slug>.md`, outside the working tree. The slug is unique per plan: the dated plan filename stem, or a spec/task slug when no plan exists; never overwrite another plan's record. Never stage it or store secrets there. Orchestrator updates the record after each accepted task commit (task ID, SHA, state). Record approved document paths/versions/coverage/dependencies and approval evidence; explicit target choice; prior and resulting Git state; document commit SHA/subject/files; task scope, ownership, checks and limits. If a gate or record was late, record actual order and resolve forward; never claim retroactive compliance.

The Coder brief supplies absolute workspace, verified branch/HEAD, canonical record path, approved task/criteria, exact file ownership, expected tests, dependency limits and blocked conditions. Restart brief: supply only verified deltas and mark unchanged fields; `unchanged` means unchanged relative to the record file the fresh Coder reads, and every other brief field is in full. Coder trusts Orchestrator verified prep rather than independently repeating approval/Git evidence checks, reads fields marked unchanged, and stops on an actual observed conflict. Tell Coder that others share the repository and unrelated work must be preserved.

Roles report directly to Orchestrator. Do not delegate at depth 2. Orchestrator sequences dependent work, resolves actual blockers and revalidates affected gates before resume. No automatic retry after unexpected Git or tool failure.

If the record write is denied or unavailable, Orchestrator carries the full record inline in every Coder brief (no delta, no record-file `unchanged`) and states why; that satisfies the accessible-record requirement. Do not delete it automatically.

## Choice lifetime and reuse

Accepted task commits do not by themselves invalidate the initial execution-target choice for the same approved scope, workspace, repository, and target; verify and reuse successful task commits without duplication. On every first start and restart recheck actual state against the brief (workspace/repository identity, branch or detached HEAD, HEAD, changes, ownership, approvals, document commits or valid absence); reuse never waives a gate. Reuse the choice only while its evidence is accessible and valid. If scope, workspace, repository, target, or approved branch candidate changes, or a failure means the old target cannot be trusted, obtain a fresh explicit choice after applicable approvals and document completeness. Authorized HEAD and dirty-state changes alone do not invalidate it; record them and verify they match approved work. State mismatches block editing until Orchestrator revalidates the gate; resolution does not by itself require a new choice unless it invalidates the old target; never fall back automatically (apply the Explicit choice rule). Inaccessible records or unclear ownership block editing; prior conversation cannot substitute for evidence.
