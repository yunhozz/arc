# 계획 문서 승인 후 일괄 실행 준비 구현 계획

> **실행 역할 안내:** Yunho Harness의 기존 역할 경로를 따른다. CEO가 승인·준비·인계·수락을 소유하고 Coder가 지정 파일을 편집한다. `writing-plans`의 별도 실행자 선택이나 추가 실행 스킬 지시는 Harness 규칙으로 대체한다.

**목표:** 현재 승인 범위에 필요한 문서를 모두 작성·승인한 뒤 체크아웃을 선택하고 미커밋 승인 문서를 한 번에 커밋하도록 Harness 계약을 명확히 한다.

**구조:** `skill/SKILL.md`에 문서 집합 완결과 준비 순서를 정의하고 README를 동기화한다. 기존 Coder 독립 확인·Git 실패 복구 계약은 보존하며 manifest 해시를 갱신한다.

**기술:** Markdown, Git, SHA-256. 새 의존성이나 실행 기능은 추가하지 않는다.

**Spec:** [`docs/superpowers/specs/2026-10-07-planning-documents-batch-handoff-design.md`](../specs/2026-10-07-planning-documents-batch-handoff-design.md)

## 공통 제약과 소유권

- 작업공간은 `/Users/ma-24-007/Desktop/workspace/yunho-harness`다.
- Coder는 `skill/SKILL.md`, `README.md`, `MANIFEST.sha256`만 편집한다.
- `agents/harness-coder.toml`, `tests/test_install.py`는 읽기 전용으로 대조한다.
- 테스트를 추가·수정·실행하지 않는다. TDD와 설치 검사 실행도 포함하지 않는다.
- 추가 파일 수정이 필요하면 편집 전에 CEO에게 보고하고 범위 승인을 받는다.
- 승인된 spec·plan과 shared brief는 CEO가 통합·저장한다.
- 이 계획 승인 전에는 체크아웃 선택 요청, 브랜치 전환, staging, 문서 커밋을 하지 않는다.
- 무관한 기존 변경을 보존한다. 자동 unstage, reset, stash, clean, 삭제를 하지 않는다.
- 기존 명시적 체크아웃 선택, Coder 재개별 독립 확인, 안전한 Git 권한 복구 규칙을 유지한다.
- 외부 스킬·설치된 사본·별도 프로젝트·권한 설정·모델·설치기는 변경하지 않는다.

## 검토 초점

1. 외부 brainstorming의 조기 spec 커밋 지시가 Harness에서 명시적으로 이연되는가.
2. 필요한 plan 일부가 미승인인데 실행 준비나 Coder 시작을 허용하는가.
3. Spike와 문서 없는 bounded 경로에서 불필요한 문서를 강제하거나 공통 게이트를 생략하는가.
4. 기존 커밋·재개를 이유로 중복 커밋하거나 새 승인 범위를 과거 승인으로 처리하는가.
5. 승인 문서 변경·추가 범위·Git 실패 시 관련 증거를 갱신하고 영향받는 실행을 중단하는가.

## 작업 0: CEO의 승인과 일괄 준비

**담당:** CEO
**입력:** 승인 spec과 이 계획의 사용자 승인
**출력:** Coder가 독립 확인할 준비 증거와 brief

- [ ] 계획 승인을 받기 전에는 실행 대상 선택이나 문서 커밋을 하지 않는다.
- [ ] 승인 후 현재 승인 범위의 적용 문서 목록, 절대 경로, 승인 버전·상태, plan 의존 순서, 생략 근거와 미완료 문서 부재를 기록한다.
- [ ] 모든 적용 문서가 승인된 다음에만 실제 저장소·작업공간·브랜치·HEAD·변경 소유권을 확인하고 사용자의 명시적 체크아웃 선택을 받는다.
- [ ] 새 브랜치를 선택하면 승인된 후보와 기준 HEAD로 같은 체크아웃에서 생성·전환하고 결과를 확인한다. 현재 체크아웃을 선택해도 경로와 상태를 다시 확인한다.
- [ ] 이미 유효하게 커밋된 승인 문서는 SHA·메시지·경로·승인 내용을 확인해 재사용한다.
- [ ] 아직 커밋되지 않은 승인 문서만 함께 하나의 집중 docs 커밋으로 준비한다. 대상 경로와 staged diff를 확인하고 첫 커밋 전에 최종 메시지를 확정한다.
- [ ] SHA·메시지·포함 경로·승인 내용·post-commit HEAD·최종 Git 상태를 확인한다.
- [ ] 실패나 부분 완료는 기존 안전 복구 계약에 따라 처리한다. 해결되지 않았으면 Coder를 시작하지 않는다.
- [ ] brief에 세 파일의 Coder 소유권, AC1–AC14, 테스트 미실행 조건, 정적 확인 범위, QA·Reviewer 의무를 기록한다.

권고 문서 커밋 메시지:

```text
docs(harness): 계획 문서 일괄 준비 설계와 구현 계획 정리
```

**완료 조건:** 계획·문서 승인 중 준비 작업을 하지 않았고, 모든 적용 승인과 필요한 Git 준비 증거가 완결됐다.

- [ ] `Design and planning`에서 적용 문서 집합과 완결을 정의한다. brief에 범위, 경로, 승인 버전·상태, plan 의존성, 적법한 생략 사유와 미완료 문서를 기록하게 한다.
- [ ] 정상 순서를 명시한다.

```text
설계 승인
→ 필요한 spec 작성·자체 검토·승인
→ 필요한 plan 작성·자체 검토·개별 승인

→ 실행 대상 선택·필요한 브랜치 전환
→ 기존 커밋 확인·미커밋 승인 문서 일괄 커밋
→ 최종 상태 확인
→ Coder 인계
```

- [ ] 외부 brainstorming의 spec 선행 커밋 지시를 최종 일괄 준비 단계까지 이연한다. written-spec 승인 후 계획 작성 순서와 외부 스킬 파일 미수정 원칙을 유지한다.
- [ ] 문서 집합이 완결되기 전에 실행 준비 목적의 체크아웃 선택 요청, 브랜치 생성·전환, staging, 문서 커밋을 하지 못하게 한다. 읽기 전용 상태 확인은 허용한다.
- [ ] Spike, bounded 계획 생략, bounded 계획 필요, architectural, 비행동 문서·설정 경로별 필요한 승인·산출물·준비를 명시한다.
- [ ] Spike probe와 후속 구현을 별도 승인 범위로 둔다. Coder가 probe를 수행하면 공통 게이트를 적용하고, Coder가 없는 읽기 전용 조사에는 Coder 게이트가 발생하지 않게 한다.
- [ ] 기존 plan 생략 기준과 위험별 QA·Reviewer 판단을 보존한다. 문서 생략을 저위험이나 게이트 면제로 연결하지 않는다.
- [ ] `Checkout approval`을 문서 집합 승인·완결 뒤 실행 대상을 선택하도록 정렬한다. 무응답 차단과 재개별 명시 선택을 보존한다.
- [ ] `Coder handoff gate`를 최초 시작과 재개 모두에 적용한다. 필요한 산출물 승인·생략 근거, 문서 집합 완결, 실행 대상, 저장소 상태·소유권, 문서 커밋 증거와 brief를 확인한다.
- [ ] `Planning document commit`에서 기존 유효 커밋 재사용, 남은 문서의 단일 집중 커밋, 전부 커밋된 경우 검증만 수행하도록 명시한다.
- [ ] 과거 커밋을 억지로 하나의 SHA로 합치기 위한 amend·reset·재커밋·빈 커밋을 금지하고 기존 메시지 선결정·staged 내용 확인·실패 차단 조건을 유지한다.
- [ ] `Handoff evidence`에 문서 목록·승인 버전·의존 순서·생략 근거·기존 커밋·일괄 커밋 및 최종 상태 증거를 추가한다.
- [ ] 계획 중·구현 중 추가 범위, 승인 문서 변경, 실행 중 Coder, 문서 변경 없는 재개의 처리 규칙을 반영한다.
- [ ] `Git metadata write denial`, `Existing changes and failures`, `New task branch`, `Current checkout`과 새 순서 사이의 모순을 확인하고 기존 보존·차단 조건을 약화하지 않는다.

**완료 조건:** 전체 적용 문서 승인 전 준비를 허용하는 문구가 없으며, 문서 생략 경로에도 공통 Coder 게이트가 유지된다.

## 의존성·가정·남은 한계

- 순서는 `작업 0 → 작업 1 → 작업 2 → 작업 3 → 작업 4`다. 모든 적용 문서의 계획 승인 전 작업 0의 실행 대상 선택·커밋 단계로 가지 않는다.

- 정적 대조와 manifest 확인은 실제 에이전트 준수, 설치된 사본 갱신, 실행 중인 에이전트 적용 또는 별도 저장소의 Git 권한 복구를 입증하지 않는다. 테스트 실행 결과도 없다.

## 자체 검토
