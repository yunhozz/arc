# ARC 정체성 전환 실행 계획

**목표:** 추적 문서·설정·역할·배포본을 ARC로 통일하고, 검토가 끝난 뒤 GitHub 저장소와 로컬 프로젝트 이름을 전환한다.

**설계:** 역할 프로필, 모델 설정, 설치기, 도구, 문서, 기존 테스트 기대값과 manifest를 한 구현 단위로 변경한다. 저장소 변경을 정적으로 수락하고 커밋한 뒤 독립 Reviewer가 전체 diff를 검토한다. CEO가 마지막으로 원격과 프로젝트 폴더를 전환한다.

**기술 범위:** Python, TOML, Markdown, SVG, Git, GitHub 저장소 설정.

**승인 명세:** [ARC 정체성 전환 설계](../specs/2026-10-16-arc-identity-design.md). 별도 사용자 승인을 받았다.

## 1. 전역 제약

- 제품명은 `ARC`, 풀네임은 `Agent Role Coordination`, 설치 식별자와 설치 경로는 `arc` 및 `skills/arc`다.
- 역할 ID는 `arc_<role>`, 프로필 경로와 Claude frontmatter 이름은 `arc-<role>`이다. 역할은 `scouter`, `planner`, `coder`, `qa`, `reviewer`다.
- 생성 블록은 `<!-- arc:begin -->`, `## Agent Role Coordination`, `<!-- arc:end -->` 형식을 쓴다.
- 현재 사용자 홈의 Codex·Claude 설치 및 설정은 열거나 변경하지 않는다.
- 기존 미추적 문서는 읽거나 검색·편집·추적하지 않는다. 새 이름으로 폴더를 옮길 때 위치만 함께 이동한다.
- 테스트를 추가하거나 실행하지 않는다. 기존 테스트는 이름 변경과 직접 연결된 fixture·경로·기대 문자열만 갱신한다. 설치기와 모델 적용기도 실행하지 않는다.
- 모델·추론 수준·도구·권한·역할 책임·승인 정책의 값과 의미를 유지한다.
- Git 이력은 재작성하지 않고 push하지 않는다.

## 2. 선행조건과 기준

**CEO 소유**

- [ ] 이 계획의 사용자 승인을 받는다.
- [ ] 승인 후 실행 위치를 명시적으로 선택받는다. 현재 checkout, 새 branch, managed worktree 중 선택 전에는 Coder를 시작하지 않는다.
- [ ] 명세·계획 승인과 실행 위치 선택을 받은 뒤, CEO가 이번 작업에서 작성한 명세·계획 두 파일만 경로를 명시해 준비 커밋한다. 기존 제외 문서는 stage하지 않으며 이 준비 커밋 뒤에 Coder를 시작한다.
- [ ] 실행 대상·기준 HEAD·허용 변경 파일과 비추적 상태를 기록한다. 현재 handoff에는 `master`와 기준 HEAD `6c482f50ab04752a9174a7f3f4b3e9fc4ec89624`가 기록되어 있다.
- [ ] 실제 이름 전환 전에 GitHub 저장소 변경 권한과 `/Users/yunho/Desktop/project/arc`의 사용 가능성을 다시 확인한다.
- [ ] 제외 문서를 포함해 비추적 파일을 stage하지 않도록 명시 파일 목록으로 작업한다.

초기 추적 inventory는 제품 표기 937건·내용 파일 75개·관련 이름이 있는 경로 16개다. 구현 시작 시 추적 인덱스와 작업 트리의 파일 목록을 새로 대조한다. 기존 미추적 문서는 어떤 검색에도 포함하지 않는다.

기존 `render_agents_md`는 관리 블록을 문서 끝에 배치하며 기존 기대값도 이 동작을 확인한다. 이름 변경만으로 동작을 바꾸지 않도록 말단 배치를 유지한다. 관리 블록을 재생성하되 블록 밖의 텍스트와 공백은 보존한다.

## 3. 작업 T1 — 추적 저장소의 ARC 이름 계약 전환

**소유:** Coder가 변경, QA가 정적 확인, CEO가 수락·커밋.

**목표:** 명세 C1 및 C3–C11을 저장소에서 충족한다. 실제 GitHub·로컬 경로 전환(C2)은 T1 뒤에 한다.

### 범위

- `README.md`, `install.py`, `MANIFEST.sha256`, `docs/images/role-flow.svg`, `codex/config.toml`.
- Codex·Claude 역할 프로필 10개 및 새 `arc-<role>` 파일 경로.
- 양 플랫폼의 `skill/SKILL.md`, `skill/models.toml`, `skill/scripts/apply-models.py`, `skill/scripts/model_config.py`.
- Codex 지침 참조 파일 2개, Claude 지침 참조 파일 4개.
- `codex/tools/codex_token_usage.py`.
- `tests/test_install.py`, `tests/test_claude_payload.py`, `tests/test_target_install.py`, `tests/test_token_usage.py`의 기존 기대값.
- 초기 inventory의 역사 문서 41개와 그중 이름 변경이 필요한 경로 6개, 새 경로를 참조하는 다른 추적 파일.

계획과 명세 파일은 Coder 편집 대상이 아니다. 다른 파일에 새로운 참조가 발견되면 Coder는 이를 임의 확장하지 않고 CEO에게 알려 허용 목록을 갱신한다.

### 단계

- [ ] **1. 기준 목록 확정 — Coder**

  추적 경로와 추적 내용만 조사해 75개 파일·16개 경로의 초기 inventory와 대조한다. 차이와 문맥상 예외를 CEO에게 보고한다. 제외된 파일이나 홈 설치는 탐색하지 않는다.

- [ ] **2. 프로필과 역할 설정 — Coder**

  역할 파일 10개를 새 경로로 이동한다. Codex 등록 키, Claude frontmatter, 두 `models.toml`, 파일 매핑, prefix 검사, 설치 목록과 문서의 역할 참조를 다섯 역할 전체에 맞춘다. 모델·추론·도구·권한 값은 변경하지 않는다.

- [ ] **3. 설치기·모델 적용기·도구 — Coder**

  제품 설치 식별자, 내부 상수·변수·함수, 동적 모듈명, 출력, 백업·스테이징·복구 접두사를 ARC에 맞춘다. 존재하지 않는 과거 폐기 프로필 정리 목록은 제거하고 새 폐기 이름을 만들지 않는다. 토큰 사용 도구의 예시는 새 역할을 쓰며 외부 로그 입력은 재분류하지 않는다.

- [ ] **4. 관리 블록 안전 규칙 — Coder**

  시작 표식과 풀네임 제목을 정확히 사용하고 종료 표식 쌍을 일관되게 생성한다. ARC 표식의 누락·중복·역순·손상과 이전 설명형 표식의 완전·불완전·혼합 형태는 어떤 파일 쓰기보다 먼저 거부한다.

  과거 표식 탐지는 제품명 리터럴 없이 일반 namespace와 관리 안내의 구조를 사용한다. 자동 이전·삭제는 하지 않는다. 기존 렌더링 인터페이스, 문서 끝 배치, 블록 밖 내용·공백 보존 동작을 유지한다. 전역 쓰기 계획 경로에서 표식 검사가 실제 쓰기보다 먼저 실행되는지 소스 흐름을 확인한다.

- [ ] **5. 문서와 역사 경로 — Coder**

  프로젝트 정체성·역할·설치 예시·경로·내부 링크를 ARC로 정규화한다. 역사 문서의 날짜, 당시 승인·검증 기록, 정책 판단 등 이름 외 사실은 보존한다. 6개 역사 문서 경로와 그 참조 링크를 함께 바꾼다. Git 이력은 재작성하지 않는다.

- [ ] **6. 기존 테스트 기대값 — Coder**

  기존 테스트의 제품명·역할·표식·제목·fixture·파일 경로 기대만 새 계약에 맞춰 고친다. 말단 배치와 비명명 assertion은 그대로 둔다. 새 테스트·새 사례·새 assertion·동작 실행이 필요해지면 편집을 멈추고 CEO에게 보고한다.

- [ ] **7. manifest — Coder**

  기존 포함·제외 규칙을 유지하고, 새 프로필 경로 및 변경된 배포 파일의 해시를 반영한다. `models.toml`은 계속 제외한다. 제품 코드나 설치기를 실행해 manifest를 생성하지 않는다.

- [ ] **8. 정적 증거 제출 — Coder**

  변경 파일 목록, 다섯 역할 대응표, 잔존 검색, 거부 검사의 호출 순서, 링크·manifest 대조, 비명명 설정 보존, 테스트 미실행을 기록해 QA와 CEO에게 전달한다.

### QA 정적 수락 기준

- 추적 내용과 경로에 이전 제품명·역할 ID가 남지 않는다. 추적 검색은 변경 후 작업 트리를 대상으로 하며 제외 미추적 파일은 검색하지 않는다.
- 역할 프로필 10개와 이름 변경 문서 경로 6개가 새 위치에 있으며, 설치 목록·모델 설정·frontmatter·매핑·문서 링크가 일치한다.
- 구 이름 별칭, 과거 프로필 ID, 자동 이전·정리 경로가 없다.
- 생성 표식·풀네임 제목·말단 배치가 명세와 기존 동작에 일치한다. 이전·손상 표식 거부가 쓰기 진입보다 먼저 호출됨을 코드 흐름으로 확인한다.
- 테스트 변경은 이름 관련 기존 기대값에 한정하고 assertion 의미를 보존한다. 테스트는 실행하지 않는다.
- 모델·추론·도구·권한·역할 정책과 외부 API 필드가 보존된다.
- 링크 대상, manifest 경로·포함 정책·해시가 맞는다.
- 전체 diff와 `git diff --check`를 확인하고 비관련 기능 변경이 없다.
- 현재 사용자 홈 설치와 제외 문서를 다루지 않았으며 제외 문서가 추적되지 않는다.

### T1 수락·커밋

CEO는 QA 결과와 잔여 한계를 확인한 뒤 T1을 수락하고 T1 파일만 명시적으로 stage해 한 번 커밋한다. `git add .` 및 `git add -A`는 사용하지 않는다. 계획·명세 준비 파일은 구현 커밋과 섞지 않는다.

예상 커밋 제목:

```text
refactor(arc): 제품·역할 식별자와 배포 경로 통합 전환
```

### T1 중단 조건

이름 변경 밖의 기능·테스트 수정, 정책 의미 변화, 역할 매핑 불일치, 링크·manifest 오류, 사용자 홈 접근 필요, 제외 파일 편집 필요, 예상하지 못한 추적 상태가 발견되면 관련 편집을 중단하고 CEO에 보고한다.

## 4. 최종 전체 검토

**시점:** T1 수락·커밋 이후, 외부 이름 전환 이전.

**소유:** CEO가 전체 변경과 기준 diff를 준비하고 Reviewer가 독립적으로 한 번 검토한다.

Reviewer는 역할·설치 계약, 표식 거부의 정적 흐름, 정책과 데이터 보존, 테스트 변경 제한, manifest와 변경 범위를 살핀다. CEO는 발견사항을 처리하고 다시 확인한다. 새 요구사항이나 승인 범위 변경이 필요하면 별도 결정 전까지 보류한다. 이 전체 검토는 T1 수락 전 QA 확인을 대신하지 않는다.

## 5. GitHub 원격·로컬 프로젝트 이름 전환

**소유:** CEO. 별도 소스 변경 커밋은 만들지 않는다.

**선행조건:** T1 수락·커밋, 독립 Reviewer 검토 완료, 필수 발견사항 처리 완료.

- [ ] GitHub 저장소 이름·변경 권한과 `/Users/yunho/Desktop/project/arc` 경로 사용 가능성을 다시 확인한다.
- [ ] 현재 branch·HEAD·추적 상태·비추적 상태를 기록한다. 제외 문서 내용은 열지 않는다.
- [ ] 실행 중 에이전트 작업을 종료하고 새 경로에서 canonical 기록에 접근할 방법을 정리한다.
- [ ] GitHub 저장소를 `yunhozz/arc`로 변경한다.
- [ ] `origin`을 `https://github.com/yunhozz/arc.git`로 설정한다.
- [ ] 프로젝트 디렉터리를 `/Users/yunho/Desktop/project/arc`로 옮긴다.
- [ ] 새 위치에서 branch·HEAD·추적 상태·origin을 읽기 전용으로 확인한다.
- [ ] 새 GitHub 저장소 정체성을 확인하고 명세 C2 증거를 기록한다.

이름 변경에는 push가 포함되지 않는다. 대상 충돌·권한 부족·부분 성공 시 다음 변경을 멈추고 실제 상태를 기록한다. 덮어쓰기·삭제·재clone·강제 복구를 하지 않는다. 폴더 이동으로 추적·미추적·ignored 상태를 그대로 보존한다.

## 6. 최종 보고와 잔여 위험

CEO는 명세 C1–C12 결과별 근거, T1 커밋 SHA, Reviewer 발견사항 처리, 최종 GitHub 이름·origin·절대 경로, 제외 상태 보존을 보고한다.

테스트·설치기·모델 적용기를 실행하지 않았음을 분명히 밝힌다. 설치 성공·멱등성·롤백·표식 거부의 런타임 결과는 검증됐다고 표현하지 않고 미검증으로 남긴다. 현재 사용자 홈 설치·설정을 읽거나 변경하지 않은 점도 기록한다. 정적 검토만으로 판단할 수 없는 중대한 위험은 완료 처리하지 않고 CEO가 사용자 지시를 받는다.

## 7. 자체 검토

- 역할·프로필·모델·설치·문서·기존 테스트 기대값·manifest를 하나의 변경 단위로 두어 부분 전환을 막는다.
- 사용자 명세의 풀네임 제목을 반영하고 이전 설계 초안의 다른 제목을 재사용하지 않았다.
- 승인 명세와 현행 renderer·기존 기대값을 대조해 말단 배치 동작을 보존 대상으로 명시했다.
- 원격·프로젝트 폴더 이름 전환은 저장소 변경의 정적 수락과 독립 검토 뒤에 둔다.
- 테스트를 추가·실행하지 않으며 그로 인해 런타임 동작은 미검증으로 남는다는 제한을 기록했다.
- 기존 사용자 설치와 제외 미추적 문서는 변경 범위 밖에 둔다.
- 이 계획과 명세는 현재 새로 작성한 비추적 문서다. 승인 후 CEO가 두 파일만 명시적으로 준비하며 제외 문서를 stage하지 않는다.
