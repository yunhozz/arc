- 계획 문서 준비 커밋과 구현 완료 후 선택할 수 있는 커밋은 분리한다. Push·merge·배포는 범위 밖이다.

## 검토 초점

1. Coder 최초 시작과 기존 Coder 재개 모두 명시적 체크아웃 선택을 요구하는가.
2. 무응답·불명확한 응답·계획 승인만으로 현재 체크아웃에서 진행하는 경로가 남아 있지 않은가.
3. 계획 문서 커밋 검증 또는 유효한 문서 생략 근거 전에는 Coder를 시작하지 않는가.
4. 무관한 staged 변경과 부분 완료를 자동으로 정리하지 않고 중단하는가.
5. Git 쓰기 거부를 lock 충돌, 샌드박스, OS 권한 문제와 구분하고 안전한 복구 후 재검증하는가.

이 항목은 문서·프로필 대조와 독립 QA·Reviewer 검토에 연결한다. 자동 테스트를 추가하거나 실행하지 않는다.

## 작업 0: CEO 인계 준비 및 문서 커밋

**담당:** CEO

1. 계획 승인을 받은 뒤 이번 Coder 인계의 실행 대상을 사용자에게 제시한다. 절대 경로, 현재 브랜치 또는 detached HEAD, 기준 HEAD를 밝히고 현재 체크아웃 또는 확인된 기준의 새 브랜치 중 선택을 받는다. 무응답은 선택으로 처리하지 않는다.
2. 새 브랜치를 선택한 경우 후보 이름·충돌 여부를 확인하고 그 후보에 대한 승인을 받은 뒤 생성한다. 실패하면 현재 체크아웃으로 자동 전환하지 않는다. 현재 체크아웃을 선택한 경우 그 선택을 brief에 기록한다.
3. 실제 저장소, 브랜치, HEAD, staged·unstaged·untracked 변경 및 편집 소유권을 확인한다. 선택된 체크아웃과 작업공간 경로를 고정한다.
4. 승인된 spec·plan만 준비 커밋에 포함되도록 대상을 정하고 첫 커밋 전 최종 메시지를 확정한다.

권고 메시지:

```text
docs(arc): Coder 인계 게이트 구현 계획 정리
```

5. stage된 경로와 diff가 승인 문서에만 일치하는지 확인한다. 승인된 spec이 이미 유효하게 커밋돼 있으므로 중복 커밋하지 않는다. 아직 커밋되지 않은 승인 plan만 필요하면 그것만 포함한다.
6. 문서 커밋 후 SHA, 메시지, 포함 경로, post-commit HEAD, 최종 브랜치 및 변경 상태를 확인해 brief에 기록한다.
7. 쓰기가 거부되면 읽기 전용으로 실제 Git 경로·lock·HEAD·index·부분 완료를 확인한다. 승인된 정확한 명령에 한정한 escalation을 요청할 수 있다. 거부되거나 상태가 불명확하면 Coder 인계를 차단한다.
8. 승인·체크아웃 선택·Git 상태·문서 커밋 증거·범위·수락 기준·테스트 금지를 brief에 기록하고, 준비 완료 전에는 Coder를 생성하지 않는다.

**완료 조건:** 이번 인계 선택과 문서 커밋 또는 생략 근거가 검증되고, 미해결 오류나 상태 변화가 없다.

## 작업 1: 공통 인계·Git 복구 계약

**파일:** `/Users/ma-24-007/Desktop/workspace/arc/skill/SKILL.md`
**담당:** Coder

1. 편집 전에 brief의 승인·체크아웃·Git 상태·문서 커밋 증거를 읽기 전용으로 대조한다. 누락·불일치 시 CEO에 반환하고 편집하지 않는다.
2. `Design and planning`의 Coder 시작 조건을 `Workspace handoff`의 단일 게이트와 연결한다.
3. `Checkout approval` 및 `Current checkout`에 매 Coder 시작·재개 전 명시적 실행 대상 선택을 반영한다. 무응답이나 승인 부재 시 현재 체크아웃으로 자동 진행하는 문구를 제거한다.
4. 새 브랜치 후보 검증·충돌·재승인·실패 중단 규칙을 유지하고, 인계 선택 없이는 Coder를 시작하지 않도록 한다.
5. 단일 인계 게이트를 문서화한다: 적용 승인, 실행 대상 선택, 저장소와 실제 Git 상태, 변경 소유권, 문서 커밋 또는 유효한 생략 근거, 최종 상태 확인, brief 증거가 전부 있어야 한다. 신규 생성과 재개에 같은 조건을 적용한다.
6. `Planning document commit`에 승인 내용·staged 경로·diff 확인, 기존 유효 커밋 재사용, 최종 메시지 선결정, routine amend 제거, 커밋 후 결과 검증을 연결한다.
7. Git 메타데이터 쓰기 거부 시 정확한 오류·Git 디렉터리·lock·프로세스·브랜치·HEAD·index·부분 완료를 안전하게 조사하도록 한다. 샌드박스 원인이면 이미 승인된 단일 Git 명령과 작업공간에 한정한 escalation을 요청한다.
8. escalation 거부·해결되지 않은 OS 권한 문제는 인계 차단으로 이어지게 한다. lock 삭제·`chmod`·`chown`·샌드박스 우회·다른 작업공간 이동·자동 reset/stash/clean을 복구 수단으로 허용하지 않는다.
9. `Handoff evidence`에 선택, 계획 문서 SHA·메시지·경로·내용, 최종 상태, 실패와 복구 증거를 반영한다.
10. diff를 승인 명세 및 AC1–AC5·AC7–AC8과 대조하고, 기존 규칙과 모순되는 자동 진행 경로가 없는지 기록한다.

**완료 조건:** 선택 부재나 준비 실패에서 Coder 시작·재개를 허용하는 문구가 없고, 기존 변경 보존 및 브랜치 실패 규칙과 새 게이트가 일치한다.

## 의존성·가정·미해결 사항

- 순서는 `작업 0 → 작업 1 → 작업 2 → 작업 3 → 작업 4`다. 의존 단계는 병렬화하지 않는다.

- 테스트 추가·실행은 사용자 요청이 없으므로 계획하지 않는다. 따라서 실제 런타임 에이전트 준수는 검증 완료라고 주장하지 않는다.
- 실제 `token-planet` 권한 문제는 별도 저장소의 승인된 Git 쓰기와 결과 근거가 있어야 해결 완료로 본다. 이 계획은 해당 저장소나 ACL을 변경하지 않는다.
- 설치된 ARC 사본은 이번 저장소 편집만으로 갱신됐다고 주장하지 않는다.
- 계획된 파일 외 변경이 꼭 필요하면 구현 전에 CEO가 수정 범위와 이유를 제시하고 승인을 받는다.
