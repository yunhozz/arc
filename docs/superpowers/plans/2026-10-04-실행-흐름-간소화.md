### 단계 6: manifest와 구조 확인

- [ ] 실제 workspace 루트에서 기존 순서·비대상 항목을 보존하며 지정 8개 digest만 갱신한다.

```python
from pathlib import Path
import hashlib

selected = {
    "skill/SKILL.md",
    "agents/harness-lead.toml",
    "agents/harness-planner.toml",
    "agents/harness-coder.toml",
    "agents/harness-qa.toml",
    "dependencies/writing-plans/SKILL.md",
    "dependencies/brainstorming/SKILL.md",
    "README.md",
}
manifest = Path("MANIFEST.sha256")
found, updated = set(), []
for line in manifest.read_bytes().splitlines(keepends=True):
    raw = line.rstrip(b"\r\n")
    parts = raw.split(b"  ", 1)
    if len(parts) == 2:
        name = parts[1].decode("utf-8")
        if name in selected:
            if name in found:
                raise SystemExit(f"Duplicate manifest entry: {name}")
            found.add(name)
            digest = hashlib.sha256(Path(name).read_bytes()).hexdigest()
            line = digest.encode("ascii") + b"  " + parts[1] + line[len(raw):]
    updated.append(line)
if selected - found:
    raise SystemExit(f"Missing manifest entries: {sorted(selected - found)}")
manifest.write_bytes(b"".join(updated))
```

## 자체 검토와 열린 결정

- Updated spec의 커밋 요구와 기준 16–18을 공통 정책·Lead·사례·실제 커밋 단계에 연결했다.
- 하나의 공유 계약 단위로 묶어 부분 수락·부분 커밋의 불일치를 피했다.
- 현재 실행의 fresh 전체 review와 향후 위험도별 정책을 구분했다.
- Existing test harness·suite를 가정하지 않았고 TDD·baseline 요구를 함께 명시했다.
- 과거 예외를 승계하지 않았으며 test-first는 정확한 개정 계획이 필요하다.
- Workspace가 미확정임을 밝히고 실제 절대 경로의 일관된 handoff를 요구했다.
- 커밋의 기존 사용자 허용을 반영했고 push·설치로 확대하지 않았다.
- Lead는 spec 기준 1–18과 전체 계획을 읽어 대조했다. Placeholder·새 모드 정의·무승인 테스트 실행·과거 예외 승계가 없음을 확인했다. Manifest 변경 8개 digest와 9개 payload의 수가 일치한다.
- 남은 결정은 계획·구체 절차 승인, TDD·baseline 처리, workspace preference·consent다. 새 설계 결정은 없다.

다음 목표는 **계획과 이번 구체 실행 절차의 승인**이다. TDD·baseline·workspace는 위 별도 gate에서 정확한 범위로 처리한다. 계획 승인 전 worktree 생성·정책 구현·검증 실행·커밋을 시작하지 않는다.
