# ARC watch 구현 계획

> **에이전트 작업자용:** 이 계획은 ARC 역할 흐름으로 실행한다. 최상위 작업(W1~W6)마다 새 Implementer가 TDD(`references/test-driven-development.md`)로 구현하고, 새 QA가 검증하며, Orchestrator가 수용한 뒤 집중 커밋 1개를 만든다. 모든 작업이 수용되면 Reviewer가 최종 전체 변경을 한 번 검토한다. 단계는 체크박스(`- [ ]`)로 추적하며, 체크박스는 커밋 단위가 아니다. S0과 B1은 Orchestrator와 QA의 사전 작업이며 커밋하지 않는다.

**목표:** Claude Code와 Codex 세션 활동을 시간순으로 합쳐 보여 주는 읽기 전용 CLI 하위 명령 `arc watch`를 추가한다.

**구조:** 표현 기본 요소(W1) → 플랫폼별 정규화(W2) → tail·범위·탐색(W3) → dispatch 색인(W4) → 엔진(W5) → CLI·root·문서(W6). 모듈은 아래 단계부터 쌓는다. 공개 표면(`arc watch`)은 마지막 작업에서만 연다.

**기술 스택:** Node.js ≥22 ESM, `node:test`, `node:fs/promises`, `node:child_process`(git만 실행). 외부 의존성 없음.

**스펙:** `docs/superpowers/specs/2026-11-11-arc-watch-design.md` (이 계획과 같은 커밋 `docs(watch): arc watch 설계 승인`). 이 계획의 "스펙 정정·보완 기록"을 함께 읽는다.

## 전역 제약

- 새 코드는 `lib/watch/` 아래에만 둔다. `lib/runtime/`, `claude/skill/runtime/`, `codex/skill/runtime/`은 **어떤 작업도 바꾸지 않는다**. 따라서 runtime 사본 재생성과 `tests/node/runtime-versions.test.mjs`의 `baselineHash` 갱신은 이 계획에 해당하지 않는다. 바뀌었다면 수용 보류 사유다.
- `lib/runtime`에서는 import만 한다. 대상은 `createLineParser`(`lib/runtime/role-observe.mjs`)와 `resolveConfigHome`(`lib/runtime/local-cli.mjs`) 두 개뿐이다.
- `lib/watch/` 파일 이름과 import 지정자에는 `tui`, `safe-fs`, `installer`가 들어가면 안 된다(`tests/node/terminal.test.mjs:7`의 hook 정규식). watch 경로는 이 세 모듈을 import하지 않는다.
- `lib/` 아래에 파일을 추가하거나 바꾼 작업은 `node scripts/update-manifest.mjs`를 실행한다. 손으로 고치지 않는다.
- 출력 라벨과 문구는 영어로 하고 ASCII 라벨 규칙을 따른다(스펙 §9, §13).
- 테스트는 실제 `~/.codex`, `~/.claude`, 사용자 HOME을 읽거나 쓰지 않는다. fixture 홈은 모두 `fs.mkdtempSync(path.join(os.tmpdir(),'arc-watch-'))` 아래에 만들고 `t.after`에서 지운다. 자식 프로세스 테스트는 `HOME`, `CODEX_HOME`, `TZ`를 임시 값으로 넘긴다.
- `tests/node/`의 어떤 파일에도 철자 오류 라벨 `'Ava'+'liable'`을 넣지 않는다(선행 계획의 `status-labels.test.mjs` 검사 대상). 원문 reason 통과 시험에는 `host_sandbox_blocked`, `permission_scope_unverified`, `custom_reason_xyz`를 쓴다.
- 공용 상수는 `lib/watch/model.mjs`의 `WATCH_LIMITS`에만 둔다. 스펙 §14 값을 그대로 쓰고 공개 옵션으로 만들지 않는다.
- 커밋 메시지 형식: `feat(watch): <한국어 요약>`. 문서가 함께 바뀌는 W6도 `feat`로 한다.

## 기준선 비교 규칙 (모든 작업 공통)

- **B1 기준선:** 기준 커밋 `$B1`은 선행 계획의 마지막 커밋 `fix(management): 설치 실행 단계의 Codex 재확인에서 app-server 제외`다(이 계획 커밋 amend 전 SHA `fd8a6dc`, amend 후 SHA는 Orchestrator handoff 기록에 둔다). 원래 적은 `f76cc77`은 rebase 전 사본이라 브랜치에 없다(2026-11-11 사용자 승인으로 교체). Orchestrator가 `$B1`에서 아래 명령으로 전체 테스트를 실행하고, 실패 이름 정렬 목록을 `baseline-failures-B1.txt`로 보관한다.
- 전체 테스트 명령(`npm test` 대신, 멈춤 방지):
  `node --test --test-timeout=120000 tests/node/*.test.mjs > <log> 2>&1`
- 판정:
  - `grep -E '^not ok' <log> | sed 's/^not ok [0-9]* - //' | sort > <current>`를 만든다.
  - `comm -13 baseline-failures-B1.txt <current>`의 출력이 없어야 한다(새 실패 없음).
  - 시간 초과로 취소된 테스트는 실패로 센다.
  - 기존 실패를 고쳤다면 `comm -23` 결과를 보고에 남긴다.
- **실행 주체:** 전체 테스트는 Orchestrator가 sandbox 밖에서 실행한 결과를 기준으로 한다. - 작업마다 쓰는 정적 검사:
  - `npm run check:manifest`
  - `npm run check:role-policy`
  - `node scripts/update-runtime-assets.mjs --check`
  - `git diff --stat $B1 -- lib/runtime claude/skill/runtime codex/skill/runtime tests/node/runtime-versions.test.mjs` (출력 없음)

## 검토 초점

1. **아주 큰 transcript나 4 MiB를 넘는 한 줄:** 시작이 느려지거나 메모리가 커지면 안 된다. 최근 이벤트는 256 KiB만, tick당 1 MiB만 읽어야 한다 → W3 `readTail sparse 64 MiB`, `tail skips a 5 MiB line` 테스트.
2. **transcript 본문의 ANSI와 제어문자(터미널 주입):** 출력 전에 제거해야 한다 → W1 `sanitizeText strips terminal control sequences`, W5 통합 테스트.
3. **`arc watch | head -3`, Ctrl-C, pane 닫힘(SIGHUP):** 0으로 즉시 끝나고 stack trace가 없어야 한다 → W6 spawn 테스트.
4. **symlink cwd(`/tmp`↔`/private/tmp`), 공백이나 Unicode가 든 경로:** 범위 판정이 틀리면 안 된다 → W3 `inScope resolves symlinked and spaced paths` 테스트.
5. **자정이나 시간대 경계에 생긴 rollout 날짜 폴더:** 놓치면 안 된다 → W3 `listCodexRollouts covers local and UTC dates around midnight` 테스트.

## 스펙 정정·보완 기록 (Orchestrator가 스펙에 반영할지 결정)

- **C1 (정정, 확인된 사실):** Codex `item_completed` `FileChange`의 `changes`는 절대 경로를 키로 하는 **객체**다(`{"/abs/path":{"type","unified_diff","move_path"}}`). 그 밖에 `status`, `stdout`, `stderr`가 있다. 근거: `~/.codex/sessions/2026/11/11/rollout-2026-11-11T10-22-58-01a1c833-*.jsonl`.
  - 계획: 경로는 객체면 키와 문자열 `move_path`, 배열이면 `path`/`file`을 쓴다. 중복을 없애고 최대 20개.
  - `unified_diff`, `stdout`, `stderr`는 어떤 모드에서도 출력하지 않는다. 이 셋을 스펙 §11과 AC-W13 표지 목록에 추가한다.
- **C2 (정정):** §19의 "전체 `npm test`가 통과"를 위 기준선 비교 규칙으로 바꾼다.
- **C3 (보완):** dispatch 이벤트의 플랫폼은 아티팩트로 정한다. `events.jsonl`에 `thread`가 있으면 codex, `init`이 있으면 claude, 매핑된 세션이 있으면 그 세션의 플랫폼이다. 모르면 사람용 platform 칸에 `arc`를 표시하고 JSON에서는 `platform`을 생략한다. `hostPlatform`으로 추론하지 않는다(AC-W18).
  - NOTICE의 JSON에도 `platform`이 없고 `source:"watch"`다.
- **C4 (보완):** `--session <dispatchId>`는 그 dispatch의 세션들을 따라간다. `--session <sessionId>`는 그 세션과 하위 에이전트를 따라가고, 그 세션 자체가 bridge 세션이면 해당 dispatch 이벤트도 포함한다. Orchestrator 세션과 그 세션이 띄운 dispatch를 이어 주는 데이터는 없으므로 연결하지 않는다.
- **C5 (보완):** `--platform`을 지정하면 플랫폼을 모르는 dispatch 이벤트(C3)는 출력하지 않는다. 그런 이벤트는 두 플랫폼을 모두 볼 때만 나온다.
- **C6 (보완, 검토 초점 2):** §11 텍스트 처리에 단계를 하나 추가한다. CSI·OSC escape sequence와 그 밖의 C0/C1 제어문자를 제거하는 단계로, 공백 합치기보다 앞에 둔다.
- **C7 (재량 고정):** §12의 이름 기반 마스킹은 키 이름이 다음 단어 가운데 하나로 **끝날 때만** 적용한다: `password`, `passwd`, `pass`, `secret`, `token`, `api_key`/`apikey`/`api-key`, `access_key`, `private_key`, `auth`(대소문자 무시). 예: `GITHUB_TOKEN=x`는 마스킹하고 `author: Kim`은 그대로 둔다.
- **C8 (정정, S0 V2):** Codex `spawn_agent` 호출의 `arguments.message`는 암호문으로 저장된다. SPAWN text는 `'<agent_type>: <task_name>'`이고 `message`는 어떤 모드에서도 출력하지 않는다(2026-11-11 사용자 승인). 함수 이름은 `name:'spawn_agent'`와 `namespace:'collaboration'`로 나온다.
- **C9 (보완, S0 V3 규칙 적용):** 웹 검색은 `item_completed` `Extension` `kind:'web.search'`로 나온다 → `tool` `web.search` + `query`. `results`, `action`은 쓰지 않는다. 그 밖의 Extension kind와 `SubAgentActivity`·`CollabAgentToolCall`·`ContextCompaction`은 `other`. Claude는 최상위 `type`으로만 분기하고 `api-request*` 줄은 버린다. Claude `system` 줄은 출력하지 않는다(V4).
