# TUI 프리셋 적용과 버전 표시 설계

## 목표

ARC 관리 TUI에서 프리셋 확인과 적용 단계를 한눈에 이해할 수 있게 하고, 버전 확인과 홈 화면의 상태 정보를 간결하게 표시한다.

## 접근 방식

기존 `ui.menu`와 `runSetup` 흐름을 유지하면서 `Performance preset` 안에 선택 및 확인 상태를 둔다. 공통 메뉴 API에 범용 화면 전환 기능을 추가하는 방법은 다른 메뉴까지 영향을 넓히므로 이번 변경에는 포함하지 않는다.

## 동작

### 프리셋 선택

- `Economy`, `Balanced`, `Smart`를 선택하면 `Performance preset` 화면을 유지하고 확인 상태로 바꾼다. 기존 선택 프리뷰 아래에 `Are you sure?`, 빈 줄 하나, `Apply`, `Back`을 표시한다.
- 확인 상태에서 `Back`을 누르면 원래 프리셋 목록으로 돌아가며, 적용 전의 설정을 보존한다.
- 확인 상태에서 `Apply`를 누르면 `Install / Update`에서는 선택을 설정 초안에 반영하고 기존 설정 흐름을 이어간다. `Change Preset`에서는 준비된 프리셋 변경 작업을 바로 실행한다.
- `Custom`은 기존처럼 Custom 편집기로 이동한다. Custom 편집기의 `Apply`는 카탈로그 검증 후 값을 즉시 반영한다. 설치 흐름에서는 설정 초안에 반영한 뒤 나머지 설정을 이어가며, `Change Preset`에서는 프리셋 변경 작업을 바로 실행한다. 편집기의 `Back`은 변경 사항을 버린다.

### 버전 확인

- 업그레이드가 가능하면 `Check Version`에는 `Upgrade`와 `Back`만 표시한다. 기존 버전·최신 버전·확인 문구는 숨긴다.
- `Upgrade`는 화면을 열 때 준비한 버전 업그레이드를 실행하고 `Back`은 홈으로 돌아간다.
- 업그레이드 성공 결과는 `Upgrade completed!` 한 줄로 표시한다.

### 홈 화면

- 설치 상태 `installed`와 `absent`는 각각 `Avaliable`, `Not Avaliable`로 표시한다. `incomplete`는 기존 의미를 유지한다.
- 실행 중인 패키지의 버전을 `ver <version>` 형식으로 로고 마지막 줄 오른쪽에 표시한다. 터미널 글꼴 크기는 바꿀 수 없으므로 텍스트를 로고보다 시각적으로 덜 강조한다.

## 범위

- 구현 대상: `lib/tui/setup.mjs`, `lib/tui/custom-preset.mjs`, `lib/tui/app.mjs`, `lib/tui/render.mjs`.
- 설치·프리셋 변경의 관리 작업, 데이터 검증, 보호 동작은 기존 경로를 재사용한다.
- 테스트 코드는 변경하거나 실행하지 않는다. 기존 화면 기대값과 달라지는 부분은 구현 후에도 검증되지 않은 상태로 기록한다.

## 확인 기준

- 일반 프리셋 선택 후 같은 화면에 확인 상태가 나타나고, `Back`은 선택 목록으로 돌아가며, `Apply`는 작업 종류에 맞게 반영한다.
- Custom의 `Apply`는 유효한 편집값을 즉시 현재 흐름에 반영하고 `Back`은 미적용 편집을 버린다.
- 업그레이드 가능 상태에는 `Upgrade`와 `Back`만 표시되며 성공 결과가 간결하다.
- 홈 상태 문구와 버전 표기가 지정된 형식으로 나타난다.

## 승인 및 계획

사용자는 2026-11-08에 이 설계 범위를 승인했다. 작업은 한정된 TUI 변경이지만 적용 시점과 화면 전환이 연결되므로 별도 구현 계획을 작성하고 승인받은 뒤 진행한다.
