# ARC 설치 시 에이전트 생성·동시 실행 한도 설정 명세

## 1. 승인 상태와 목적

사용자는 기본값을 **누적 생성 100개, 동시 실행 5개**로 정한 설계에 대해 “이 설계로 진행 (권장)”을 선택했다.

승인 범위:

- CLI 설치에서 두 한도를 입력받고 영속화한다.
- 동시 실행 한도는 ARC 정책과 지원되는 플랫폼 네이티브 설정에 반영한다.
- 누적 생성 한도는 ARC의 prompt-level 정책으로 관리한다.
- 설치기가 Codex 설정을 직접 병합하게 되면 수동 예시인 `codex/config.toml`을 제거하고 현재 의존 검사를 갱신한다.

설계 깊이는 Architectural이다. 이 명세의 개별 승인이 끝난 뒤 구현 계획을 작성한다.

## 2. 설정과 적용 범위

| 설정 | CLI 플래그 | 최초 기본값 |
|---|---|---:|
| 누적 생성 한도 | `--max-total-subagents` | 100 |
| 동시 실행 한도 | `--max-concurrent-subagents` | 5 |

두 한도는 **하나의 ARC 루트 coordination tree/session**에 적용한다. 루트 Orchestrator는 계산에서 제외하며, 독립적인 Codex와 Claude 세션 사이에 예산을 공유하지 않는다.

누적 한도는 역할 종류와 관계없이 생성된 고유 서브에이전트 인스턴스의 총수다. 완료된 인스턴스와 모든 자손을 포함한다. 기존 depth-2 역할의 위임 금지는 유지한다.

동시 한도는 같은 tree에서 현재 실행 중인 인스턴스 수다. 실행 중인 turn이나 background 작업이 있는 인스턴스를 포함하고, 완료 결과를 반환해 현재 실행 중인 turn이 없는 인스턴스는 제외한다. 플랫폼 네이티브 카운터가 완료된 thread 등을 계속 포함하면 실제 사용 가능 용량은 더 작을 수 있다.

`max_concurrent_subagents > max_total_subagents`도 유효한 설정이다. 실질적인 실행 가능 수가 더 낮다는 사실을 표시하고 자동으로 값을 보정하지 않는다.

## 3. 누적 예산과 생명주기

Orchestrator는 세션 장부에서 다음 상태를 구분한다.

- 생성이 확인된 고유 인스턴스와 누적 사용량
- 현재 실행 중인 인스턴스
- 생성 요청 중이거나 생성 여부가 불확실한 예약

생성 전에는 남은 누적 예산과 동시 실행 용량을 확인하고 예약한다. 여러 생성을 병렬 요청할 때는 예약 합계도 확인한다.

- 생성 성공: 예약을 누적 사용량으로 전환한다.
- 생성되지 않았음이 확정된 실패: 예약을 해제한다.
- 생성 여부가 불확실한 실패: 확인 전까지 예약을 유지한다.
- 완료·종료: 동시 실행 용량은 복구하지만 누적 예산은 복구하지 않는다.
- 동일 인스턴스에 후속 메시지를 보내거나 재개: 누적 사용량을 추가하지 않는다.
- 새 인스턴스를 생성·교체·재시작: 누적 사용량을 추가한다.

작업 완료, 사용자 후속 요청, 대화 압축, 설치 재실행은 같은 루트 세션의 사용량을 초기화하지 않는다. 새 독립 루트 세션은 새 예산을 갖는다. 기존 세션을 재개하면 장부를 이어 사용한다.

장부는 Orchestrator의 세션 문맥과 기존 handoff 기록에 보존한다. 압축 또는 인계에는 사용량·예약·활성 인스턴스·남은 예산을 포함한다. 장부를 복원할 수 없으면 0으로 추정하지 않고, 추가 생성 전에 불확실성을 보고한다.

누적 예산이 부족하면 추가 생성을 중단하고 남은 필수 단계와 필요한 예산을 보고한다. 기존의 fresh Coder·fresh QA·독립 Reviewer 등 게이트를 생략하거나 다른 작업에 인스턴스를 재사용해 우회하지 않는다.

이 장부와 한도 준수는 **prompt-level 정책**이다. 기술적으로 우회할 수 없는 spawn 제한을 제공한다고 설명하지 않는다.

## 4. 설정의 영속 원본

플랫폼별 설치 경로에 다음 파일을 둔다.

- Codex: 해석된 `CODEX_HOME/skills/arc/limits.toml`
- Claude Code: `~/.claude/skills/arc/limits.toml`

파일에는 다음 필드를 저장한다.

| 키 | 의미 |
|---|---|
| `version = 1` | 형식 버전 |
| `max_total_subagents` | 승인된 누적 생성 한도 |
| `max_concurrent_subagents` | 승인된 동시 실행 한도 |

이 파일은 ARC 정책값의 영속 원본이며, 세션별 사용량은 저장하지 않는다. Orchestrator는 첫 서브에이전트를 생성하기 전에 파일을 읽고, 실행 중인 세션은 시작 시 읽은 설정을 유지한다. 재설치한 값은 새 세션부터 적용하며 진행 중인 세션의 예산을 초기화하지 않는다.

파일이 없거나 잘못되었거나 지원하지 않는 버전이면 명확히 보고하고, 검증되지 않은 값으로 서브에이전트를 생성하지 않는다. 재설치는 기존 값을 안전하게 읽어 생략된 값을 보존한 뒤 새 skill tree에 포함한다. 관리 디렉터리 교체로 사용자 한도가 기본값으로 돌아가서는 안 된다.

## 5. 플랫폼 네이티브 설정

| 플랫폼 | 대상 | 설정 |
|---|---|---|
| Codex | 해석된 `CODEX_HOME/config.toml` | `[agents].max_concurrent_threads_per_session` |
| Claude Code | `~/.claude/settings.json` | `env.CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` |

Codex 값은 TOML 정수, Claude 값은 환경변수 문자열로 기록한다. 누적 생성 한도는 이 키들에 기록하지 않는다.

네이티브 설정은 플랫폼 런타임에 전달하는 동시성 설정이다. ARC의 활성 인스턴스 수와 네이티브 thread/subagent 카운트가 완전히 동일하다고 보장하지 않는다. 더 낮은 실제 제한, 계정·관리 설정, 환경변수 우선순위, 지원 버전의 제약을 따른다.

설치 성공은 설정 파일 변경 성공을 의미한다. 지원 버전에서 네이티브 설정이 실제 적용되는지 확인하지 않았다면 런타임 검증이 완료됐다고 표현하지 않는다. 기존 Codex의 `CODEX_HOME` 해석과 Claude의 기본 설정 디렉터리 제한은 유지한다.

## 6. 입력·대화형 동작

새 플래그는 install에만 추가하며 uninstall의 `targetOnly` 선택 흐름은 유지한다. 숫자는 ASCII 십진 정수로 입력받고 앞뒤 공백은 제거한다. 값은 1 이상 `Number.MAX_SAFE_INTEGER` 이하여야 한다. 음수·0·소수·지수 표기·부호·누락·중복 옵션은 거절한다.

대화형 설치에서는 기존 target/preset 선택 이후 누락된 한도를 질문한다.

- 누적 생성 한도: 기존 ARC 값, 없으면 100을 기본값으로 표시한다.
- 동시 실행 한도: 기존 ARC 값, 없으면 5를 기본값으로 표시한다.
- Enter는 표시된 값을 선택한다.
- 명시한 CLI 플래그는 다시 묻지 않는다.
- 잘못된 숫자는 설명하고 같은 입력을 다시 받는다.
- 취소·EOF 시 파일 변경 없이 종료하고 터미널 상태를 복구한다.

`--target all`에서는 두 설정의 입력을 공통으로 받는다. 입력한 값은 양쪽에 적용한다. 기존 플랫폼별 값이 다르면 각각 표시하고 Enter는 해당 값을 유지한다고 안내한다. 신규 대상은 최초 기본값을 사용한다.

target/preset 플래그가 있어도 TTY에서는 누락된 한도를 질문한다. 모든 값이 명시되면 질문하지 않는다.

## 7. 비대화형·재설치·사용자 설정 보존

비대화형 설치는 현재처럼 `--target`과 `--preset`을 요구한다. 새 플래그는 선택 사항이다. 각 정책값의 해석 순서는 다음과 같다.

1. 명시한 CLI 값 또는 대화형 선택
2. 기존 ARC `limits.toml` 값
3. 최초 기본값 100/5

기존 ARC 설정이 손상되면 기본값으로 덮어쓰지 않고 실패한다.

최초 설치에서는 해석된 동시 한도로 네이티브 대상 키를 설정한다. 대상 키가 이미 있으면 이전 값과 새 값을 요약에 표시한다. 이 키는 이번 기능이 의도적으로 관리하며 다른 사용자 키는 보존한다.

재설치에서 저장된 ARC 동시 한도와 네이티브 값이 다르고 사용자가 동시 한도를 새로 지정하지 않았다면, 사용자 변경일 수 있으므로 덮어쓰지 않고 쓰기 전 충돌을 보고한다. 대화형 질문에서 값을 다시 선택하거나 명시 플래그를 전달하면 그 값으로 갱신한다. 대상 키가 없다면 충돌로 보지 않고 해석된 값을 추가한다.

설치 요약에는 플랫폼별 최종 정책값, 네이티브 이전 값과 변경 예정값, 보존·미변경·충돌 상태를 표시한다. 관련 없는 설정 전체나 환경변수 전체를 출력하지 않는다.

## 8. 안전한 병합과 실패 처리

Codex 병합은 기존 `[agents]` 테이블과 다른 키·주석을 보존하고 중복 테이블을 생성하지 않는다. 다른 유효한 TOML 표현도 의미를 바꾸지 않고 안전하게 수정할 수 있을 때만 처리한다. 수정 전후를 파싱해 대상 키 이외의 의미가 유지되는지 확인한다.

Claude 병합은 root JSON object와 `env` object를 검증하고 다른 기존 키를 보존한다. `env` 타입 충돌이나 모호한 설정은 덮어쓰지 않고 실패한다. JSON 재직렬화로 공백·들여쓰기가 바뀔 수 있지만 다른 값의 의미는 유지한다.

파싱 실패, UTF-8 오류, 경로 안전성 위반, 동시 수정 감지, 지원하지 않는 설정 구조는 쓰기 전에 실패시킨다. 명시 요청의 일부를 건너뛰고 전체 성공으로 보고하지 않는다.

새 `settings.json` 경로와 생성되는 `limits.toml`을 기존 snapshot·managed-path·transaction 관리에 포함한다. 파일별 렌더러 선택의 위치 의존성을 제거하고 파일 역할에 따라 렌더러를 선택한다. 실패 시 기존 rollback 규칙을 적용하고 복구 실패·잔여 경로를 보고한다.

`--target all`은 현재처럼 Codex 다음 Claude 순서로 각각 설치한다. Claude 실패 시 성공한 Codex는 유지하며 양쪽 전체가 하나의 원자적 트랜잭션이라고 설명하지 않는다.

## 9. `--check`·`--dry-run`·`--skip-global`·제거

`--check`와 `--dry-run`은 같은 입력 해석·설정 파싱·충돌 검사를 수행하되 파일을 변경하지 않는다. 기존 네트워크 미사용 동작을 유지한다. `--dry-run`은 플랫폼별 정책값과 변경 예정 경로·이전 및 새 값을 표시한다. `--check`는 설정을 적용하거나 런타임 제한을 검증한 것으로 표현하지 않는다.

`--skip-global`은 전역 instruction·Codex config·Claude settings·기존 shell 접근을 건너뛴다. ARC 내부의 `limits.toml`과 skill은 설치한다. 이 경우 “ARC 정책만 적용, 네이티브 설정 미변경”을 명시한다. 접근하지 않은 전역 파일의 충돌을 검사했다고 주장하지 않는다.

제거 시 `limits.toml`은 ARC skill과 함께 제거한다. 네이티브 동시성 키는 기존 Codex wait 설정처럼 유지하며 제거 출력과 README에 설명한다. 과거 값 자동 복구는 추가하지 않는다.

## 10. ARC 정책·문서·수동 샘플

두 플랫폼 `SKILL.md`와 planning/handoff 참조에서 고정된 four 제한을 제거하고 `limits.toml` 및 실제 런타임 용량을 따르도록 변경한다.

첫 생성 전 설정 로드, 예산 예약, 누적 장부 유지, 소진 시 보류 동작을 추가한다. 설정 가능한 동시성은 기존 작업 독립성, 동일 파일 편집 금지, 역할 소유권, 의존성·승인 규칙을 완화하지 않는다.

직접 설치 병합이 구현되면 저장소의 `codex/config.toml`을 삭제한다. 이 파일은 현재 수동 병합 예제이며 npm payload와 manifest 대상이 아니다. 현재 직접 의존하는 `tests/test_arc_policy.py:469–472` 및 `:1358–1362` 검사는 새 정책·기본값 검사로 교체한다.

README에는 두 옵션, 기본값, 세션 범위, 정책/네이티브 차이, 재설치와 충돌, `--skip-global`, 적용 시점, 제거 시 키 유지 동작을 설명한다. completion과 관련 CLI 안내도 갱신한다. 변경된 보호 payload에는 정상 manifest 생성 절차를 적용한다. 관련 없는 과거 기록과 기존 미추적 문서는 유지한다.

| AC10 | 정책 준수 검사와 네이티브 런타임 적용 증거를 구분해 보고한다. |

필수 검증 범위는 CLI/PTY 입력과 취소, 기본값·재설치·설정 충돌, TOML/JSON 보존, 다중 대상, dry-run/check/skip-global, transaction 실패·rollback이다.

정책 행동 사례에는 누적 한도 직전 병렬 예약, 완료 후 예산 미복구, 동일 인스턴스 재사용, 불확실한 생성 결과, 낮은 네이티브 용량을 포함한다. 정책 텍스트 검사가 실제 에이전트 준수나 하드 강제를 입증했다고 주장하지 않는다.

지원 플랫폼 새 세션에서 네이티브 설정 적용을 확인한다. 플랫폼/버전별 확인이 불가능하면 해당 범위를 검증되지 않았다고 명시하고 완료 판단을 Orchestrator에 넘긴다.
