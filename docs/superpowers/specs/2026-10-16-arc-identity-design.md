# ARC 정체성 전환 설계

## 1. 목표

저장소와 프로젝트의 제품 정체성을 **ARC (Agent Role Coordination)**로 통일한다. 제품을 설명하는 추적 문서·설정·역할 ID·파일 경로와 GitHub 및 로컬 프로젝트 이름을 함께 바꾼다.

현재 조사 기준으로 추적 내용에는 제품명 관련 표기가 937건, 포함 파일이 75개이며, 이름에 이전 제품 식별자가 포함된 추적 경로가 16개다. 이 수치는 초기 조사값이며 구현 전 전체 추적 파일을 다시 확인한다. 변경은 문맥을 검토하며 수행하고, 정책의 의미나 외부 API 필드명은 이름 변경만으로 바꾸지 않는다.

## 2. 이름 계약

| 대상 | 새 이름 |
|---|---|
| 제품명 | `ARC` |
| 풀네임 | `Agent Role Coordination` |
| 설치 식별자 및 스킬 디렉터리 | `arc`, `skills/arc` |
| 로컬 프로젝트 경로 | `/Users/yunho/Desktop/project/arc` |
| GitHub 저장소 | `yunhozz/arc` |
| Git 원격 URL | `https://github.com/yunhozz/arc.git` |

다섯 역할의 단일 식별자는 다음과 같다.

| 역할 | 식별자 | Codex 프로필 | Claude 프로필 |
|---|---|---|---|
| Scouter | `arc_scouter` | `codex/agents/arc-scouter.toml` | `claude/agents/arc-scouter.md` |
| Planner | `arc_planner` | `codex/agents/arc-planner.toml` | `claude/agents/arc-planner.md` |
| Coder | `arc_coder` | `codex/agents/arc-coder.toml` | `claude/agents/arc-coder.md` |
| QA | `arc_qa` | `codex/agents/arc-qa.toml` | `claude/agents/arc-qa.md` |
| Reviewer | `arc_reviewer` | `codex/agents/arc-reviewer.toml` | `claude/agents/arc-reviewer.md` |

Codex 설정 키와 양 플랫폼의 `models.toml` 역할 키는 `[roles.arc_<role>]` 규칙을 따른다. Claude 파일의 frontmatter `name`도 파일명과 같은 `arc-<role>` 값으로 한다. 설치기, 모델 적용기, 토큰 사용 도구, 프로필 매핑, 문서 예시와 기존 테스트 기대값은 이 대응을 일관되게 사용한다. 구 이름의 별칭이나 호환 프로필은 제공하지 않는다. 외부 API 필드, 모델, 추론 수준, 도구, 권한과 역할 책임은 유지한다.

## 3. 범위

변경 범위는 저장소의 추적 파일, GitHub 저장소 이름과 원격 URL, 프로젝트 폴더 이름이다.

- README, Codex·Claude 지침, 설정, 설치 스크립트, 역할 프로필, 모델 설정 및 적용 코드, 토큰 사용 도구의 프로젝트 정체성 표기를 갱신한다.
- 역사 문서의 제품명·역할·설치 예시·프로젝트 경로와 내부 링크를 현재 이름에 맞게 정규화한다. 날짜, 당시 승인·검증 기록, 정책 결정 등 이름과 무관한 사실은 보존한다. Git 커밋 이력은 재작성하지 않는다.
- 프로필 10개와 역사 문서 6개의 경로를 아래 새 경로로 옮긴다.

```text
claude/agents/arc-coder.md
claude/agents/arc-planner.md
claude/agents/arc-qa.md
claude/agents/arc-reviewer.md
claude/agents/arc-scouter.md
codex/agents/arc-coder.toml
codex/agents/arc-planner.toml
codex/agents/arc-qa.toml
codex/agents/arc-reviewer.toml
codex/agents/arc-scouter.toml
docs/superpowers/arc-alignment-brief.md
docs/superpowers/plans/2026-10-03-arc-alignment.md
docs/superpowers/plans/2026-10-07-arc-preaction-gates.md
docs/superpowers/plans/2026-10-07-token-efficient-arc.md
docs/superpowers/specs/2026-10-03-arc-alignment-design.md
docs/superpowers/specs/2026-10-07-arc-preaction-gates-design.md
```

- `MANIFEST.sha256`의 경로와 해시를 변경된 배포 파일에 맞춘다. 기존 포함·제외 정책은 유지하고 포함 범위를 넓히지 않는다.
- 토큰 사용 도구는 새 역할 예시를 사용한다. 외부 로그 입력은 그대로 분류하며, 과거 입력을 이전하거나 재분류하지 않는다.

이번 작업에서는 기존 미추적 문서를 열거나 검색·편집·추적하지 않는다. 그 문서는 프로젝트 폴더 이동이 필요한 경우 위치만 함께 바뀐다.

## 4. 현재 사용자 설치 보존

현재 `~/.codex`와 `~/.claude`의 설치·설정은 열람, 이동, 삭제, 갱신하지 않는다. 저장소의 미래 설치 동작과 프로필만 ARC 계약으로 바꾼다. 별도 설치 이전 기능이나 자동 정리는 만들지 않는다.

설치 식별자와 신규 설치 경로는 `arc` 및 `skills/arc`를 사용한다. 설치기 안의 백업·스테이징·복구 접두사와 출력도 제품 전용 이름을 사용한다. 기존 경로 안전성, 백업, 동시 변경 감지와 롤백 계약은 보존한다.

## 5. 관리 블록 계약

생성하는 블록은 정확히 다음 형식이다.

```md
<!-- arc:begin -->
## Agent Role Coordination

...
<!-- arc:end -->
```

시작 표식 뒤에는 괄호 설명이나 다른 suffix를 붙이지 않는다.

| 입력 상태 | 처리 |
|---|---|
| 표식이 없음 | ARC 블록을 추가한다. |
| 정상 ARC 블록 한 개 | 블록 본문만 갱신한다. |
| 갱신 결과가 현재 내용과 같음 | 파일 내용 변화 없이 종료한다. |
| ARC 표식이 누락·중복·역순이거나 형식이 잘못됨 | 쓰기 전에 거부한다. |
| 이전 설명형 관리 표식이 존재함 | 자동 이전하지 않고 쓰기 전에 거부한다. |
| ARC 표식과 이전 설명형 표식이 함께 존재함 | 쓰기 전에 거부한다. |

이전 형식은 제품명 문자열을 코드에 남기지 않고, `install.py` 관리 안내가 포함된 일반 namespace 표식 문법으로 탐지한다. 불완전한 시작·종료 표식도 거부한다. 이 탐지는 삭제나 이전을 위한 것이 아니다. 다른 프로그램이 같은 설명형 문법을 사용하면 보수적으로 거부될 수 있다. 오류에는 대상과 자동 이전을 지원하지 않는다는 점을 설명한다.

전역 지침을 변경하는 경로에서는 이 검사를 파일 쓰기 전에 수행한다. `--skip-global`은 전역 지침을 생략하는 기존 의미를 유지하며, 기존 설치를 이전하는 방법으로 안내하지 않는다. 블록 밖 내용과 공백·줄바꿈 보존 계약은 유지한다.

## 6. 프로젝트 폴더와 원격 전환

추적 파일 변경과 정적 수락 확인을 마친 뒤 다음 전환을 수행한다.

1. 원격 이름과 권한, 목표 프로젝트 경로가 여전히 사용 가능한지 다시 확인한다.
2. GitHub 저장소를 `yunhozz/arc`로 이름 변경한다.
3. 로컬 `origin`을 `https://github.com/yunhozz/arc.git`로 설정한다.
4. 프로젝트 디렉터리를 `/Users/yunho/Desktop/project/arc`로 옮긴다.
5. 새 위치에서 branch, HEAD, 추적 상태와 원격을 읽기 전용으로 확인한다.

이름 변경에는 push가 포함되지 않는다. 원격 전환과 폴더 이동은 하나의 원자적 작업이 아니므로, 일부만 성공하면 그 실제 상태를 기록하고 다음 조치를 판단한다. 대상이 충돌하면 덮어쓰거나 기존 폴더를 삭제하지 않는다. 재clone이나 강제 복구도 하지 않는다. 미추적·ignored 상태는 그대로 보존한다.

## 7. 정적 수락 및 테스트 제한

테스트를 추가하거나 실행하지 않는다. 기존 테스트 파일은 이름 변경에 따른 기존 fixture·경로·기대 문자열의 직접적인 갱신만 허용한다. 새 사례나 새 assertion은 만들지 않는다. 설치기, 모델 적용기 등도 실행하지 않는다.

구현 후 다음 정적 증거를 확인한다.

- 추적 파일 내용에서 프로젝트의 이전 이름과 이전 역할 식별자가 남지 않았는지 전체 검색한다. 미추적 문서는 검색 대상에서 제외한다.
- 경로에 이전 식별자가 포함된 추적 경로 16개가 새 이름으로 이동했는지 확인한다.
- 다섯 역할의 프로필, frontmatter, 모델 키, 매핑, 설치 목록, 도구 참조가 표의 대응과 일치하는지 확인한다.
- 관리 표식 문자열과 이전 설명형 표식의 거부 경로를 검토하고, 쓰기 진입보다 거부 검사가 먼저임을 소스 흐름으로 확인한다.
- 변경된 내부 링크의 대상이 존재하는지 확인한다.
- manifest의 대상 경로, 포함·제외 범위 및 계산 해시를 정적으로 대조한다.
- `git diff --check`, 전체 변경 범위, 정책 의미와 비관련 파일의 변경 여부를 확인한다.
- 원격 URL과 프로젝트 경로 변경 결과를 읽기 전용으로 확인한다.
- 현재 사용자 설치를 건드리지 않았으며 제외 문서가 추적되지 않았음을 확인한다.

최종 보고는 정적 확인과 실행되지 않은 동작 검증을 분리하며, 테스트 미실행을 명시한다. 설치 성공, 멱등성, 거부 동작의 런타임 결과는 검증됐다고 표현하지 않는다.

## 8. 수락 기준

| ID | 조건 |
|---|---|
| C1 | 추적 내용과 경로에서 제품 정체성이 ARC로 통일되고 프로젝트 소유의 이전 이름·역할 ID가 남지 않는다. |
| C2 | GitHub 저장소, `origin`, 로컬 프로젝트 경로가 각각 2절의 ARC 대상으로 전환된다. |
| C3 | 미래 설치 식별자는 `arc`이고 현재 사용자 설치·설정은 읽거나 변경하지 않는다. |
| C4 | 생성 블록이 정확한 시작 표식, `## Agent Role Coordination` 제목, 종료 표식을 사용하며 이전 설명형 블록은 쓰기 전에 거부한다. |
| C5 | 다섯 역할의 Codex·Claude 프로필, 모델 설정, 코드 참조와 설치 목록이 대응하고 구 이름 별칭이 없다. |
| C6 | 관련 기존 테스트의 기존 기대값과 manifest가 새 계약에 맞는다. 테스트는 실행하지 않는다. |
| C7 | 역사 문서의 제품·역할·경로 참조가 정규화되며 이름 외 사실과 Git 이력은 보존된다. |
| C8 | 제외된 미추적 문서와 그 외 미추적·ignored 상태를 편집·추적하지 않는다. |
| C9 | 추적 경로 16개와 그 경로를 참조하는 링크·예시가 함께 변경된다. |
| C10 | 모델, 도구, 권한, 역할 책임, 승인 정책의 값과 의미가 유지된다. |
| C11 | 토큰 사용 도구는 새 역할 예시를 사용하고 로그 입력은 이전·재분류하지 않는다. |
| C12 | 결과 보고에서 정적 증거, 원격·폴더 전환, 테스트 미실행과 런타임 미검증을 구분한다. |

## 9. 위험과 중단 조건

| 조건 | 대응 |
|---|---|
| 프로필·모델·설치 사이 이름 불일치 | 수락을 보류하고 공통 대응표를 기준으로 수정한다. |
| 치환으로 역할·정책 의미가 달라짐 | 변경을 보류하고 문맥별 판단을 기록한다. |
| 구 관리 블록 검사가 쓰기 뒤에 수행됨 | 구현 수락을 보류한다. |
| 별칭·과거 프로필 경로가 배포본에 남음 | 호환 예외로 묵인하지 않고 범위를 재검토한다. |
| 현재 사용자 설치 변경이 필요해짐 | 승인 범위 밖이므로 해당 단계에서 중단한다. |
| GitHub 이름·경로 충돌 또는 권한 부족 | 덮어쓰지 않고 실제 상태를 보고한다. |
| 제외 문서의 편집·추적이 필요해짐 | 해당 작업을 진행하지 않는다. |
| 링크·manifest·정적 계약 불일치 | 수락을 보류한다. |
| 테스트 없이 판단할 수 없는 중대한 동작 위험 | 테스트를 임의 실행하지 않고 잔여 위험을 보고해 지시를 받는다. |

## 10. 자체 검토

- 사용자 승인에 맞춰 역할 식별자와 역할 파일 이름도 ARC로 전환한다.
- 시작 표식은 설명 없이 정확히 `<!-- arc:begin -->`로 두고, 블록 제목에는 풀네임을 사용한다.
- 역할 프로필, 모델 설정, 설치기, 적용기와 도구를 하나의 이름 계약으로 묶어 부분 변경 위험을 다룬다.
- 과거 관리 표식은 자동 이전하지 않고 쓰기 전에 거부한다. 탐지용 코드가 구 제품 문자열을 새 배포본에 남기지 않도록 일반 namespace 규칙을 지정했다.
- 현재 사용자 홈의 설치·설정은 읽거나 변경하지 않는다. 별칭, 재설치, 자동 정리도 범위에서 제외했다.
- 제외 미추적 문서의 내용을 조사하거나 바꾸지 않으며, 추적 범위에 포함하지 않았다.
- 기존 테스트 내용의 기계적 기대값 변경만 허용하고 테스트 실행은 계획에서 제외했다. 따라서 설치와 런타임 거부 동작은 정적으로만 검토되며 실행 증거가 없다는 제한을 수락 기준과 보고 요구에 명시했다.
- 새 로컬 경로는 현재 비어 있고, 브랜치·HEAD는 handoff 기록에 보존했다. 원격 대상과 권한은 실제 전환 직전에 재확인해야 한다.

이 문서는 구현 계획이 아니다. 명세 승인을 받은 뒤에만 의존성, 작업별 소유권, 정적 수락 증거와 중단 조건을 담은 계획을 작성한다.
